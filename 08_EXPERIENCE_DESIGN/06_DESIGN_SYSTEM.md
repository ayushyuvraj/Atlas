# Design System

## Document Status

**Layer:** 8 - Experience Design
**Version:** v1.0
**Status:** Frozen
**Source:** Derived from UI/UX design-system guidance and Atlas product requirements.
**Purpose:** Define the MVP design system foundations for Atlas.

---

## Design System Principles

1. Clarity before decoration.
2. Dense but readable layouts.
3. Progressive disclosure for complexity.
4. Strong distinction between AI-generated and human-approved content.
5. Status, confidence, and risk must be visually legible.
6. Accessibility is a baseline requirement.

---

## Typography

Recommended direction:

- Display and interface headings: Lexend or similar enterprise-readable sans-serif
- Body and dense text: Source Sans 3 or similar highly readable sans-serif

Rules:

- Body text should default to at least 16px.
- Dense metadata may be smaller only when still readable.
- Line height should support scanning and table readability.
- Avoid negative letter spacing.

---

## Color Roles

Use semantic color roles rather than raw color decisions in components.

| Role | Purpose |
| --- | --- |
| Background | Page and workspace base |
| Surface | Panels, cards, tables, drawers |
| Border | Panel and table separation |
| Text Primary | Main readable text |
| Text Secondary | Metadata and supporting text |
| Action Primary | Main action |
| Action Secondary | Secondary actions |
| Risk High | High-risk state |
| Risk Medium | Medium-risk state |
| Risk Low | Low-risk state |
| Confidence High | High-confidence signal |
| Confidence Medium | Medium-confidence signal |
| Confidence Low | Low-confidence signal |
| AI Generated | Content generated by AI |
| Human Approved | Human-reviewed or committed content |

---

## Spacing

Atlas should use compact enterprise spacing:

- 4px for micro alignment
- 8px for tight internal spacing
- 12px for compact component spacing
- 16px for standard panel spacing
- 24px for section spacing
- 32px for major layout separation

---

## Layout Rules

- Use persistent navigation on desktop.
- Use responsive collapse for smaller screens.
- Avoid horizontal scroll except for explicitly scrollable tables.
- Keep action buttons stable and predictable.
- Reserve space for loading and generated content to avoid layout shift.

---

## Status Indicators

Required status types:

- Lifecycle state
- Evidence completeness
- Assumption status
- Risk severity
- Recommendation confidence
- Human review state
- Decision commitment state

---

## Motion

Motion should be subtle and functional:

- 150-300ms transitions
- Loading feedback for reasoning
- No decorative motion
- Respect reduced-motion preferences

---

## Decision

Freeze this design system foundation for Layer 8.

Layer 12 implementation may translate these rules into actual tokens and components.
